  * `smegma` 行だけを見ると `隔離・修復待ち` と `配備設定: あり` が並び、Overview を見ない限り「APIで機械出力受付が停止されている」と分からない。
  * `knotted_penis` の `記録された停止条件` や `ada_wong` の `測定を止めた条件` の中身が行に書かれていない。
  * `horse_penis` で `訂正記録: 25116` と `正しい例 20件 または 誤付与の訂正 50件を追加する` の関係が分からず、どの訂正がどのモデルに入ったかも追えない。
* **具体的な実装内容：**
  1. **状態セルへのAPI遮断バッジ統合：** `配備設定: あり/なし` と並べて、Overview の停止リストに含まれるタグ（`bar_censor`, `condom_on_penis`, `mosaic_censoring`, `smegma`）には行内にも **`自動付与: API受付停止中`**（それ以外は `自動付与: 有効` または `未配備`）を明示する。
  2. **停止条件・保留理由の具体表示：** バックエンドに記録されている停止・保留理由（例：正例不足、評価標本分割不可、閾値未達など記録済みの条件名、未記録なら「理由コード未記録」）を `knotted_penis` や `ada_wong` の行内に直接出力する。
  3. **訂正カウントの基準明示：** `訂正記録` 列が「全期間累計」なのか「現行配備モデル（例：`release 15`）以降の新規分」なのかを列見出しまたはセル内内訳（例：`累計 25,116件（最終評価反映後の追加: X件）` ※DBに記録がある場合のみ表示し、記録がない場合は「モデル反映時点の紐付け未記録」と明記）として表示し、`horse_penis` 等の「正例20件 / 誤付与訂正50件」が何に対する不足分かを明確にする。

### 修正3：スナップショット取得時刻・タイムゾーン表記の統一と、既定ソートの有意味化（`freshness`, `exploration`, `consistency` の同時解消）
* **現状の問題：** `候補・タグ集計は読み込み時点の記録です` とあるが読み込み時刻自体が表示されておらず、Overview の生ISO時刻（`2026-11-15T21:19:55.140592+00:00`）と実験カードのローカル時刻（`11/16/2026, 4:55:07 AM`）で形式がバラバラである。また既定ソートの `未解決の不一致` は大半の行が `0 (0 / 0)` で機能していない。
* **具体的な実装内容：**
  1. Overview と Tags ヘッダーに共通のデータ取得時刻（例：`集計取得: 2026-11-16 06:35 JST (X分前)`）を表示し、画面内の全タイムスタンプを同一タイムゾーン・同一フォーマット＋相対経過時間に統一する（`進捗が最後に増えた時刻: 未記録` と `観測時刻` の分離表示はそのまま維持する）。
  2. 状況別グループ化の順序およびグループ内既定ソートを、ほぼ全行 `0` の `未解決の不一致` から、実際に行動優先度や規模が分かる順（例：①API停止中／隔離・修復待ち → ②利用者対応（`担当: 利用者`） → ③システム停止条件あり、グループ内は `訂正記録` 降順または `候補の適合率` 順）に変更する。
