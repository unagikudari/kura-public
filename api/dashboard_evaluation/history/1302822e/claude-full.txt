## Improvement priority

1. State the completion condition (criteria 2, 6, 5).
2. Show the fetch time on the request card and render the summary's `observed_at` (criterion 4).
3. Drop the first table row's duplicate link, or replace it with `上の依頼を参照` (criterion 3).
4. Reduce or unstick the mobile header (criterion 10).
5. Give the 0-state progress bar a visible track (criterion 8).
6. Reword `検証` to `メモリ観測` (criterion 2).

## The one next small improvement

Replace the two always-visible notes under the card with a single line that says when the user is done, and move the set-scoping sentence into `集計と公開について`:

> 迷う画像は飛ばして構いません（「なし」扱いにはなりません）。最後まで一度見終えたら完了です。残りの扱いと公開可否は担当エージェントが進めます。

This removes the "must I reach 341/341?" doubt, which is the largest burden on the user, and it cuts visible text by about a third. It is copy-only.

The wording is only safe if the agent really does proceed on partial coverage. If that policy does not hold, state the real threshold in that line instead.
